# 知识星核 · 四界追光

四人同屏答题游戏，用一条故事主线串起来：**魔君打碎知识星核、把碎片撒进各界，四人小队沿星门一界一界追回**。面向希沃等教室一体机设计，分辨率 1920×1080。

## 在线地址

无需下载，浏览器直接打开：

**https://tardis923.github.io/Classroomarena/**

> 网址区分大小写，只有 `Classroomarena`（首字母大写）能打开。建议在希沃浏览器里加到书签或设为主页。**地址不要改**：存档按域名隔离，换域名/仓库名/协议（http↔https）会读不到旧进度；`file://` 本地打开与网页也是两套独立存档。

**故事主线**：星核碎片散落各界；每夺回一片，星图就亮一块并指出下一界坐标——**没有「最后一片」**，坐标会不断浮现。星核会按当地法则给四人换身行头（森林→魔法师、草坪→植物、海底→潜水服、沙漠→沙漠装束），所以换背景不是换游戏，是追到了下一界。开放式设定，后续可在星图末尾继续追加新的一界，文案里也刻意不写死结局。

## 全屏

- **只用页面顶部的一个按钮切换进入 / 退出全屏**（一体机实测后去掉了右下角的悬浮退出按钮）：
  - 首页右上角「⛶ 全 屏」↔「⛶ 退 出 全 屏」（与班级标签、⚙ 管理设置并排）
  - 关卡挑战页左上角「全 屏」↔「退出全屏」（与「设置」并排）
  - 热身赛 HUD 里新增「⛶ 全 屏」↔「⛶ 退 出 全 屏」
  - 首页内嵌的管理帧里也保留左上角这个按钮（只隐藏「设置」），点击通过 `postMessage({type:'fsToggle'})` 让父文档代为切换，不需要键盘 Esc
  - 统一由 `FS.bindButton(id, 全屏文案, 普通文案)` 绑定，文案随 `fullscreenchange` 自动变化
- **浏览器规则**：`requestFullscreen()` 是绑在当前文档上的，**跨页面跳转时会自动退出全屏**；只有按 **F11**（浏览器窗口级全屏）才会跨页保留。新页面也不能在加载时自动请求全屏（缺少用户手势）。
- 因此做了「续接」：首页处于全屏时点「学院晨练 / 关卡挑战」，跳转前写入 `arena_fs_keep_v1` 标记；新页面加载后等**用户第一次点击**时自动重新进入全屏，然后清掉标记。反过来从关卡挑战、热身赛跳回首页同理（`js/fullscreen.js` 统一处理）。点全屏按钮本身不会触发续接，避免「刚进入又被退出」。
- 首页内嵌的管理帧**没有导航**，首页全屏时它自然保持全屏。

## 分辨率与触摸自适应

舞台按 1920×1080 设计，用 `fit()` 计算 `scale(s)` 并居中；三个页面都监听 `resize` / `orientationchange` / `fullscreenchange` / `visibilitychange` / `visualViewport.resize`，全屏切换后还会延迟 120ms 重算一次，避免窗口尺寸尚未更新就取到旧值。

一体机在非 1920×1080 分辨率、系统缩放或较老内核下，浏览器对 CSS `transform` 的触摸命中测试可能把触点判到相邻按键（表现为「按 1 却输入了别的数字」）。因此答题区不再信任 `e.target`：

- `hitPanelButton(clientX, clientY, box)` 把触点换算回 1920×1080 舞台坐标，直接对按钮矩形做命中，边缘留 18px 容差；仅当坐标法失败才回退 `e.target`。关卡挑战与热身赛都走这套逻辑。
- `pointOf(e)` 兼容没有 `clientX` 的老内核 `touchstart`（从 `touches[0]` 取坐标）。
- `tapGuard` 在 60ms 内吞掉同一坐标的重复触发，防止 pointerdown 与合成鼠标事件导致一次点击输入两个字符。
- 四个角色区域各 480px 宽，随舞台整体等比缩放，不改变相对布局。

### 一体机长时间使用的加固

- **触屏手势**：三个页面统一 `touch-action:none` / `user-select:none` / `-webkit-touch-callout:none`，并拦截 `contextmenu` / `dragstart` / `selectstart`，避免长按弹系统菜单、双击放大、误选文字。首页原先只做了 tap-highlight，已补齐。
- **全屏切换后重算缩放**：`fit()` 在 resize / 旋转 / fullscreenchange / 可见性 / visualViewport 变化时重算，并在 120ms、320ms 各补算一次（全屏动画期间窗口尺寸会变）。
- **设置页暂停降频**：打开管理设置时 `parkBattle()` 会暂停战斗与答题（`B.paused`），canvas 被暗遮罩盖住后渲染降到约 5 帧/秒省 CPU；**结算页不降频**，通关礼花 `winburst` 仍按全帧率播放。
- **错误可诊断**：`tickTimers` 的技能回调异常原本被空 `catch` 静默吞掉（表现为「答对了却没放技能」且查不到原因），现在会打印 `timer:`；`render()` 分段与 `drawFx()` 逐特效也各自打印错误，一体机内核缺少某个 Canvas API 时能直接定位。
- **全屏续接标记带过期**：`arena_fs_keep_v1` 改存时间戳，**30 秒后自动作废**。避免「跳转后没点就离开页面」导致下次打开任意页面第一次点击被突然拉进全屏；旧格式 `'1'` 会自动清除。
- **长跑资源**：`B.fx` / `B.floats` / `timers` 都会随过期清理，60 秒满负载模拟峰值分别 28 / 36 / 33，无累积泄漏。
- **建议（代码外）**：一体机请在系统电源设置里关闭自动息屏；浏览器若支持 `navigator.wakeLock` 也可后续加屏幕常亮（本地 `file://` 环境下 API 可能不可用）。

## 一体机部署：确认是不是最新版

三个页面（`index.html` / `warmup.html` / `boss-battle.html`）都加了 `no-cache` 响应头，并在 `window.ARENA_BUILD` 暴露构建日期（当前 `2026-11-10f`）。

- **老师自查**：首页「⚙ 管理设置」→ 输入管理密码 → 设置页说明下方显示「构建版本 2026-11-10f」。日期是旧的就说明浏览器还在用缓存，需要强制刷新（Ctrl+F5）或清缓存后重新打开。管理帧里也能看到同一行。
- **控制台自查**：F12 执行 `ARENA_BUILD`。
- **典型症状对照**：「第一关大招 P1 有动画、P2/P3 没有」是 11-08 之前旧版的 `dc is not defined` 错误——P2/P3 才会出现「免疫灼烧/冰冻」状态栏文字，旧代码在这里求值未定义变量，导致 `render()` 中断、后面的特效/飘字/横幅全不画。新版已修掉该变量，并把 `render()` 拆成分段隔离，任何一段出错都不会再吞掉特效。看到旧构建日期即可确认是缓存问题。

## 班级名怎么设 / 怎么改

首页右上角只显示班级名，**没有「切换班级」按钮**（避免学生误改）。设定方式按运行环境二选一：

| 环境 | 做法 | 作用范围 |
| --- | --- | --- |
| **GitHub Pages 网页访问（推荐）** | 每台一体机把带参数的网址设为主页／书签：`https://tardis923.github.io/Classroomarena/?class=三年级二班`；也可以把 `班级入口-示例.html` 复制到桌面，用记事本改一行班级名，双击进入 | 只对该机器生效，打开一次即写入本机，之后正常访问也一直有效 |
| **本地 `file://` 运行** | 用记事本改 `class-config.js` 里的 `className: '三年级二班'`，保存并刷新 | 只对该机器上的这份文件生效 |

优先级：**网址 `?class=` > `class-config.js` > 本机已存班级名 > 首次弹出签到界面**。想改名字，用带新 `?class=` 的网址打开一次即可覆盖。

> 注意：网页访问时读的是 **GitHub 上的** `class-config.js`，改一体机本地的副本不会生效（浏览器也不允许网页随意读本机文件）。这个文件适合"本地运行版"或"给所有机器设同一个默认名"（改仓库后 Push）；**每台机器不同名字请用 `?class=` 网址**。班级名存在 `classarena_class_v1`，不影响关卡进度、成长和星尘。

**星尘规则（已简化）**：

- 热身赛**通关**（60 秒内星门充能到 100%）→ 奖励 **30 点**星尘；失败（超时）→ 不产星尘。
- **充能规则**：答对一题 **+2.5%**（约 40 题充满），答错一题 **−2%**，**5 秒没答题 −1.5%**（四人各算各的，防止有人挂机等队友），都按 2 秒缓慢漏掉；充能条连续平滑变化。
- 关卡挑战**每次开战都要付 30 点门票**，打输门票不退——但班级进度永久保留。
- 存**本机浏览器**（localStorage），关机、关页面都还在；每台一体机各自保存，各班进度天然隔离。
- 老师如果只想让两个游戏各自独立玩，可在关卡挑战的设置页把**「星尘门票」关掉**。

> **⏱ 热身赛限时 60 秒**：右上角显示「剩 xx s」，最后 15 秒变红闪动。
> - 超时 → 黑屏「闯关失败」+ 重来按钮，本局不产星尘。
> - 通关 → 庆祝页显示用时 / 答对题数 / 每人贡献和奖励的 30 星尘，一键挑战第一关。
> 想改规则：打开 `js/game.js` 最上面，`TEAM_TIME`（秒）、`CHARGE_ADD`（答对加）、`CHARGE_SUB`（答错扣）、`CHARGE_IDLE`（挂机扣）、`IDLE_MS`（几秒算挂机）都可直接改。

## 热身赛怎么玩

双击 `index.html` 也能从首页进入，无需安装任何东西；在线地址与本地版本完全一致（但两者的本地存档互相独立）。

1. 场景固定为**星空学院 · 星门充能**：四位星图学员**侧身骑原地发电单车**（侧脸、前倾身体、双腿一直蹬踏板），答对一题就猛蹬一脚，星尘从车上的发电机汇入中央星门；充能条持续平滑上涨，**答错会缓慢漏能 3 秒**，靠继续踩踏补回（不再是拿食物砸魔王的旧样式，全程不张嘴）。
2. 点「开始比赛」，倒计时后开跑：四人同时答题，答对充能 +2.5%、答错 −2%，60 秒内充满 100% 即通关。
3. **两类题各约一半**：①「乘法口诀 ± 一个数」（如 `7 × 8 + 5`、`6 × 9 − 4`，数字键盘输答案）；②安全知识（ABCD 四选一，即点即判）。**不再出语文 / 英语题**。题目由 `js/questions.js` 的 `QGen.table()` 与安全题库 `SAFE_BANK` 生成。
4. 通关后结算页显示奖励的 30 星尘和班级星尘池进度。

### 答题体验

- **连击**：连续答对显示「🔥xN」，3 连、5 连、10 连飘大字爆星星；答错清零。
- **答错处理**：数学题答案框短暂显示正确答案；选择题**只把选错的选项标红，不提示正确选项**，1 秒后自动换新题（避免学生靠乱点套出答案）。
- **全班一起算**：四块面板的题目始终可见，台下同学可以跟着一起答。

### 第一关 · 魔法师大战魔王

治疗师 / 雷电法师 / 火系法师 / 冰系法师四人同时各答各的题，谁答对谁立刻释放技能，合力打倒三阶段进化的「知识大魔王」；Boss 按秒出手——普攻随机队友，每隔一段时间放「天降陨石」打击全体。

- **答错就换题**：立即刷新成新题（红闪＋飘字），且我方每累计答错 3 题 Boss 回血 8%（可调）。
- **治疗师**：答对给血量最少的队友回血；累计答对 10 次（可调）触发全队回血；**全员满血时改为给全队套护盾**（可叠加，Boss 大招一击砸碎）。
- **三种答题方式自动切换**：数字键盘（口算）、`>` `<` `=` 大键（比大小）、ABCD 四选一（知识题库）。
- **难度随 Boss 阶段递增**：P1 用基准年级，P2 升一年级、P3 再升一级（封顶六年级）。
- **阶段免疫**：第 2、3 阶段 Boss 免疫灼烧与冰冻；大招间隔 30 → 20 → 10 秒越来越快。
- **班级成长代替残局反击**：早期只有第一关时的「队友倒下 +10% 攻击」愤怒机制已移除；现由通关次数提供全队攻击 / 血量 / 治疗永久 +2%（上限 +20%）。
- **跳过 / 换一题上限**：每人每局 6 次，按钮显示剩余次数，用完置灰。

- 英语覆盖颜色、动物、食物、文具、家庭、身体、数字、星期月份、天气、交通、日常交际与基础语法；
- 安全知识原有 209 题覆盖交通、消防、防溺水、饮食卫生、用电、居家、校园、防拐防骗、自然灾害、急救、出行；另从桌面《安全知识.txt》导入 **200 题**（交通 40 / 日常生活 40 / 用水 20 / 用电 40 / 用火 30 / 饮食 15 / 校园 15），源文件里每题 A 为正确答案，导入时保持 `{q, o, a:0}` 格式。

- **答案不固定在 A**：题库源文件统一把正确答案写在 `o[0]`，但 `shuffleBank()` 会在**每次页面加载**时打乱每题的四个选项并重算 `a`，正确答案随机落在 A/B/C/D（409 题实测四个位置各约 1/4）。函数用 `Math.random()` 自包含，不依赖各页面的 `ri()`，热身赛与关卡挑战都会调用。
- 加题方法：直接在 `js/banks.js` 里往 `CN_BANK` / `EN_BANK` / `SAFE_BANK` 加 `{q, o:[4个选项], a:0}`（正确答案写第一个，加载时自动洗牌）。注意四个选项不要重复，否则学生看到两个一样的选择。

技能组是全新的「**沙漏时序**」，四个技能分别属于**四种不同机制类型**，和前三关（单发 / 连射 / 印记连携）都不重复：

| 角色 | 技能 | 机制 |
| --- | --- | --- |
| 绿洲医官 · 泉泉 | 绿洲甘泉 | **持续再生**：给最虚队友挂 4 次每秒回血（HOT），不是一次性治疗 |
| 沙雷术士 · 沙雷 | 地脉蓄雷 | **延迟爆发**：先预警，蓄力 1.2 秒后落下一记高伤害重击 |
| 烈日祭司 · 炎阳 | 烈日祝福 | **当场半伤 + 可叠增益**：答对立刻打一发 0.5 倍火焰弹，并给全队叠一层 +25% 增伤；**最多 3 层**（+75%），每层独立计时 8 秒，满层时续掉最早过期那层 |
| 流沙守望 · 沙漏 | 流沙陷坑 | **吞大招**：每答对叠 1 层（上限 2），下次万针蝎雨触发时消耗 1 层、跳过本次伤害，倒计时照常重置 |

大招也从陨石/巨人/墨汁换成「**万针蝎雨**」：满屏金色针雨 + 每名角色被一簇毒针扎落、扬起沙尘。四个技能都围绕「时间」做文章，呼应沙漏与流沙；`B.sunStacks` 用「到期时间戳数组」存每一层，`sunLevel()` 在取层数时顺手清掉过期层，不用逐帧递减。

> **平衡调整**：流沙陷坑原本是每答对一次给大招倒计时 `+8` 秒，只要沙漏每 8 秒内答对一题，大招就**永远放不出来**（模拟里正常节奏大招次数为 0；沙漏缺席时反而 12/12 灭团），整关难度全绑在一个角色身上。现改为**消耗型**：`B.pitStacks` 最多 2 层，`meteorAttack()` 开头消耗 1 层并跳过本次大招，倒计时在 `tickBoss` 里照常重置。另加 `B.pitGuard`：**吞过一次后下一次大招必定命中**，避免沙漏答题快时把每次大招都吃掉（最多吃掉一半）。沙漏答对仍有明确反馈，状态栏显示 `🕳陷坑 xN`。

### 数学出题规则（第一关 + 热身赛，题型按年级累加）

- **三年级**：① 两个两位数相加减（如 `43 + 27`）；② 乘法口诀 ± 一个数（如 `7 × 8 + 36`）；③ 比大小（如 `27 + 18 ○ 53 − 9`）。
- **四年级**：＋ 整除除法；**五年级**：＋ 两位数 × 一位数 ± 一个数；**六年级**：＋ 三位数 ÷ 一位数再加减。
- 所有除法一律整除，减法不出负数；**混合运算结果不超过 200，含乘法的积不超过 150**。

## 后续想加新关卡怎么办

1. **只能追加在 `STAGES` 数组末尾、id 递增**，绝不重排编号或往中间插——`bossbattle_progress_v1` 里的 `unlocked` 是数字，插队会让老班级解锁错关。把 `done` 改成 `true`，写好 `subj`（默认学科）、`hpMul` / `atkMul`（难度系数）、`intro` / `outro`（故事文案）。
2. 首页 `index.html` 的 `WORLDS` 数组同步加一个界卡片（星图节点），星图是开放式的，末尾本来就有「更多坐标」的余地。
3. 需要新主题时仿照第二～四关：加一套 `XXX_PHASES` / `XXX_HEROES` 主题数据 + `isStageN()` 分支（背景 / 角色 / Boss / 大招演出）。第三、四关各自演示了换整套技能组：`castSeaSkill()` 用 `B.tide` 印记连携，`castDesertSkill()` 用四种时间机制，都独立于前两关的 `castSkill()`。四关都已做完，再加新关时往 `STAGES` 与首页 `WORLDS` 各追加一条即可。
4. 需要新题库时在 `js/banks.js` 里加一个数组并接入。

**旧存档兼容**：新代码读取旧的 `bossbattle_progress_v1` / `bossbattle_cfg_v1` 时会自动补默认值，进度、成长、星尘、密码都不丢；只要 Pages 地址不变，更新网页不会清掉任何一体机的数据。
